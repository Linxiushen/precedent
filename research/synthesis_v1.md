# Orchestrator's synthesis v1 (2026-09-14) — after two gap analyses (scientist, safety) + critic

Supersedes synthesis_v0.md. v0's three-camp framing and "acceptance problem" survive; several of v0's novelty claims do NOT. Corrections first.

## A. What v0 got wrong (corrected by evidence)

1. **"Nobody has a sequential test" — FALSE as invention, TRUE as adoption.** PACE (arXiv 2606.08106, June 2026) is a paired anytime-valid e-process commit gate; it measures that greedy "keep if score went up" commits **30–42% false and 10–33% harmful edits** and cuts eval cost ~18%. SEA (2607.00871) issues anytime-valid certificates for harness edits. HGM/RQGM use Beta posteriors. **Zero of the 64 deep-read frameworks use any of them.** PACE is validated only on 0.5B–3B Qwen prompt edits on GSM8K/SVAMP/ARC — single-objective, binary metric, no per-task floor, no archive-level multiple testing, no non-stationary streams. ⇒ The contribution is *integration + extension* (multi-objective, per-task floors, sequential candidates from one archive, real logs), not invention.

2. **"Nobody does counterfactual replay" — FALSE.** Causal Agent Replay (2606.08275) does do-intervention replay of recorded trajectories (for failure attribution, not gating). Counterfactual Trace Auditing (2605.11946) pairs with/without-skill traces on SWE-Skills-Bench and finds **+0.3pp** for LLM-written skills. SkillOpt-Sleep has sandboxed "tool-aware replay"; SkillMisevo-Gym records clean-session replay.

3. **The Replay Gap (2608.08239) is a direct threat to the cassette idea.** After a *model swap*, 74–77% of forks diverge at the first post-fork action; only 3% of replayed states remain valid; a log-stitching replay evaluator mispredicted every success-relevant outcome. A harness edit is a smaller perturbation, but *the edits worth evaluating are exactly the ones that change actions*. ⇒ **A cassette is a regression / behavior-change detector, not a fitness function.** Correct scoping: (a) replaying the UNEDITED harness against its own cassettes gives the baseline divergence rate = the missing noise model, for free; (b) prefix-valid counterfactuals for idempotent tools; (c) on divergence → branch into a git-snapshot sandbox and re-execute for real, terminal check = the session's own final verification (the tests the user ran). This must be *measured*, not assumed: divergence-point distribution for real refiner edits is an unmeasured quantity and itself a paper.

4. **"Camp B is unusable by app developers" — overstated.** GEPA/DSPy (38k★, Databricks production) and SkillOpt-Sleep (Claude Code/Codex plugin) are usable. The camps "do talk": Reef wraps GEPA/SkillClaw/Meta-Harness/SAO behind one propose→paired-evaluate→decide contract. Better explanation of the camps: the **RSI survey's verification hierarchy** (formal > execution > learned judge > self-assessment) — a project's camp is determined by which signal its domain makes available.

5. **Camp B's evaluator-integrity failures are all ONE bug and it is not an AI problem:** the proposer's filesystem view includes the evaluator or its data (DGM#35 hidden tests in /polyglot; HyperAgents#39 test labels in the workspace; HGM diagnosis sees the private test patch; AHE#15 forgeable best_ever.json; SIA#36 gold answers in the feedback prompt; karpathy/autoresearch#599 four working exploits incl. a fabricated 0.05 bpb that is KEPT; pi-autoresearch editable measure.sh). A mount namespace + a hash-bound score receipt would have prevented all seven. All seven were filed by outsiders and are unanswered.

## B. What v0 got right, sharpened

- **Per-task regression floor (claim 3): agree**, with the nuance that at n=2 a per-task floor is itself noise (a 60%-pass task "regresses" 40% of the time) → it is a multiple-testing problem entangled with the sequential gate; k-of-n confirmation or racing per task.
- **Safety in the gate (claim 4): agree, and it is the cheapest unclaimed paper.** Misevolve: memory alone drops refusal 99.4→54.4% with no adversary. SkillMisevo-Gym: 21/21 evolved configs author unsafe artifacts; carryover ASR 16→35%. SafeEvolve is post-hoc governance, not a gate term. A 30–100-prompt domain-conditioned canary suite costs ~50–100 LLM calls per candidate. **The loops change safety far more reliably than they change capability** (capability gains sit within noise: Meta-Harness +1.7pt, HGM 2/60 tasks, HyperAgents n.s.).
- **Loop-health telemetry (claim 5): agree, sharper.** Hermes#95976: the flagship loop was killed by two *safety guards interacting* (read-before-write × skill_view dedup) — 100% of skill updates refused for weeks, with the per-fork result logged and nobody alerted. Also: several "evolved" artifacts never reach the agent (EvoMap#624 inject drops strategy text; AutoResearchClaw loads only the first 5 alphabetical skills; ECC evolved skills land outside discovery paths; Continual Harness logs new components as failures). ⇒ **An activation probe ("is the promoted thing actually loaded?") would catch more real bugs than a fitness function.** Funnel: proposed → accepted → activated → attributed, with alarms.
- **Evaluator Goodhart (claim 6): partially.** Two distinct failure classes conflated as "reward hacking": *tampering* (fix = sealed evaluator, mount namespace, receipts) vs *overfitting via feedback* (SkillOpt#154 copies judge regex into the skill; fix = scorer-blind feedback channel + mutation-content scan + independent-family judge spot checks). RQGM's evaluator co-evolution does not fire at practical budgets (0 replacements at 128 outcomes).
- **Cross-instance merge (claim 7): agree**, genuinely open (Byzantine-robust aggregation of text artifacts; FederatedSkill 2606.03143 is the only framing).

## C. The decisive observations (from the analysts)

- **All five 2026 surveys list the same four open problems — reference implementation of a gated update loop, regression/retention protocol, evaluator co-evolution without self-confirmation, multi-generation benchmark — and none ships code.** Survey saturation is complete; a runnable reference is worth more than another taxonomy.
- **Adoption is anti-correlated with gating** (ECC 256k, Hermes 244k, autoresearch 95k, OpenViking 37k have no outcome gate; SkillOpt/GEPA/Reef/Self-Harness are 1–3 orders smaller). Verification is a UX cost the market selects against. **A gate will only spread if it is invisible until it blocks something.**
- **Five independent 2026 results converge on "LLM-written persistent artifacts have near-zero causal effect"** (CTA +0.3pp; SkillsBench 0 gain for LLM-written vs +16.2 human-written; Continual Harness 6.4% reuse; Demystifying Agent Skills precision 29.6→3.3% at 100 skills; SkillOpt gains carried by 1–4 edits). Sociological datum: Hermes ran for weeks with 0 skill updates and nobody noticed. ⇒ The "null-effect audit" of production stores is a cheap, high-impact paper; and a gate that rejects most production edits "for free" is *correct behavior*, not a bug.
- **"Proposer authors its own test" is a recurring production pattern** (EvoMap genes ship `node --version` as validation; SIA agent writes evaluate.py → abstention gives 75% reported vs 4.5% real; pi-autoresearch lets the agent decide KEEP; R-Zero/Agent0 use policy majority vote as label). Cheapest fix in the field: **the harness owns the test.**
- **Rejected edits are a free labelled negative dataset** almost nobody uses (only SkillOpt's rejected buffer and Reef's max_rejected_history). GEPA#379: same parent re-proposes identical failed mutations.
- Lin et al. (2605.30621): harness-updating ability is flat from 9B to Opus 4.6; harness-benefit non-monotonic → **spend money on evaluation replicates with a cheap proposer**, not on an Opus effort=max proposer at 10M tokens/iter (Meta-Harness).
- AI2 (2607.12227): harness evolution does not consistently beat plain test-time scaling at matched budget → every claim must be cost-normalized against a task-level-search baseline.

## D. What the RSI wave adds (to be filled from W3) — framing hypothesis
"RSI" in Sept 2026 discourse = the loop where an AI system improves the machinery that improves it (Data-RSI / Harness-RSI / Model-RSI per MetaRSI). The community consensus (Weng, Anthropic Institute, RSI survey) is that near-term RSI is *harness-first* and that its bottleneck is **verification** ("exchange rate of grounding"). Nobody ships the verification layer. ⇒ The framework should be positioned as **the verification/acceptance layer for harness-RSI**: the thing that turns "my agent modified itself" into "my agent's modification was tested, gated, activated, attributed, and can be reverted" — with the same discipline software CI/CD brought to human code changes.

## E. Refined design thesis for the design phase (one stance among several; judges decide)

**"CI/CD for self-modifying agents"** — a harness-agnostic acceptance layer that is invisible until it blocks something:
1. **Sealed evaluator boundary + score receipts** (mount namespace; sha256(evaluator, data shard, candidate, workspace state); harness owns the test). Fixes all seven Camp-B leaks; systems engineering, ~days.
2. **Statistically honest default gate**: paired candidate-vs-incumbent on identical instances; PACE-style anytime-valid sequential stop; per-task never-regress floor with k-of-n confirmation; multi-objective (accuracy × tokens × latency × safety) as constraints + Pareto; rejected-edit archive fed back to the proposer. ~500-line library with adapters for existing gate call-sites (GEPA accept, Self-Harness run_acceptance_gate, Reef decide, SkillOpt gate, Hermes skill_manage, Prime refine, ECC instinct promote, Claude Code skill/CLAUDE.md edits).
3. **Safety canary inside accept()**: 30–100 domain-conditioned probes (refusal, injection, destructive-action, reward-hack) seeded from SkillMisevo-Bench / MemEvoBench / Agent-SafetyBench; re-validate on reuse-in-new-context.
4. **Cassette regression corpus + divergence-aware replay**: record real sessions via hooks (verified working on Claude Code 2.1.258 via PreToolUse updatedInput + PostToolUse updatedToolOutput, $0.007/replay); past successes = protected regression corpus; baseline self-divergence = noise model; on divergence → git-snapshot sandbox re-execution; terminal check = session's own verification. Honest scope: regression/behavior-change gate, not a fitness function.
5. **Loop-health funnel** proposed→accepted→activated→attributed with alarms; activation probe; attribution via paired replay or clade-style pooled outcome stats on artifacts (HGM's metaproductivity idea applied to skills).
6. **Provenance taint** on every artifact (user text / tool output / web / other agents) → stricter gate for untrusted-derived artifacts; recall-by-provenance.
7. **Post-acceptance canary + auto-revert** with known-safe checkpoints, rollback depth > 1.
8. **Gate benchmark**: inject known-good/neutral/harmful edits into existing loops; report the acceptor's confusion matrix (false-commit, harmful-commit, missed-improvement), evals-per-decision, safety decay, retention — the multi-generation benchmark the surveys ask for; Reef #357/#358 opened the need on 2026-09-09.

Killer demo (5 min): `pip install X; X watch` on a Claude Code / Hermes user's machine → next morning: "12 self-modifications proposed by your agent this week: 3 accepted, 6 rejected (would have regressed on 4 of your own past tasks), 2 blocked (safety canary), 1 never activated (your harness didn't load it — here's why)". Paper claim: on the published Camp-B runs' own ledgers, X's gate would have rejected N% of accepted edits as noise and caught M% safety regressions, at K% of the eval cost.

Open decisions for the user: name; Python vs TypeScript (Claude Code hooks are language-agnostic; Hermes is Python; pi/Prime is TS); first adapter (Claude Code is the user's own harness and has the richest hook surface); license.

## F. Measured on the builder's own machine (2026-09-14, research/tools/cassette_extract.py)
7 Claude Code sessions with tool calls, 2,062 tool calls total. Replayability classes (heuristic, conservative): WORKSPACE_WRITE 50.4% (Bash mutations, Edit/Write), EXTERNAL 19.8% (WebSearch/WebFetch/gh api/Artifact/Agent spawns), IDEMPOTENT_READ 16.5%, NONDETERMINISTIC 13.2% (date/sleep/ps/polling). The idempotent-only prefix before the first non-idempotent call is 0–1 calls in every session. ⇒ **Pure VCR replay is dead on arrival for real coding sessions (consistent with The Replay Gap).** The replay design must be *sandbox-first*: workspace ops re-execute for real inside a git-snapshot sandbox (deterministic given the same state), externals + nondeterministic calls are served from the recording keyed by (tool, normalized input), and the first call that matches neither is the divergence point. Terminal check = the session's own final verification (tests the user ran) re-executed in the sandbox. Cassette raw material exists on every Claude Code user's disk with no new instrumentation (`~/.claude/projects/<proj>/<session>.jsonl`, complete tool_use↔tool_result pairs incl. structured `toolUseResult`).

## G. Gate statistics measured by simulation (research/tools/gate_power_sim.py, 2026-09-14)
- Greedy "keep if mean went up" at ZERO true lift: 44–46% false commits (N=20/40/80) — reproduces PACE's 30–42% finding.
- Anytime-valid paired betting gate (alpha=0.05, mixture over q∈{0.6..0.9}, learns only from discordant pairs): false-commit ≤4% at any N. Power on BINARY outcomes is low: incumbent 0.7 → +10pp lift detected 11% (N=40) / 39% (N=160); +20pp: 44% / 98%; +30pp: 98% at N=40 (median 22 tasks). ⇒ With 20–40 recorded tasks and binary signals, the gate reliably (a) blocks regressions/safety violations, (b) accepts only LARGE lifts, (c) must keep accumulating evidence post-acceptance (canary; the test is anytime-valid so it can continue across days), and (d) should use richer per-task signals (steps-to-done, tokens, divergence step, judge score) to raise power. This is consistent with the null-effect literature: most production edits are ≈0 and will correctly never commit.
- Per-task "never-regress" floor on stochastic tasks (pass prob 0.6): false-block 93–100% at k=1, 44–91% at k=2, 13–43% at k=3. ⇒ The protected corpus must contain only tasks with OBSERVED stability (incumbent passes k/k, measured baseline self-divergence), and a flip counts only after k-of-n confirmation. Real test-verified coding tasks are far more deterministic than Bernoulli(0.6) — the baseline self-replay measures this per task for free.
