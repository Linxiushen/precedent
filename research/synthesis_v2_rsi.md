## 1. What "RSI" means in September 2026 (and how to position)

- Three altitudes: **model-level RSI** (improve the process that makes models: RSI-Exam, AI4AI-Bench, PostTrainBench — sober numbers: best 0.46–0.51 vs 0.60 frontier reference; visible→sealed drop 12–25% for every model), **harness-level evolution** (frozen model, loop edits prompts/skills/memory/tools/control flow — where most papers and all the mass-market "self-improving" agents live), **open-ended RSI research** (Gödel lineage; bearish near-term consensus: Princeton/MIT-TR study, Jack Clark, METR expenditure horizon "minimal effect").
- Shared vocabulary to ADOPT: RSI survey 2607.07663's **verification hierarchy** (formal verifiers > execution feedback > learned judges > intrinsic signals) — "the difference between a loop that improves and a loop that circles is one rung of external verification"; MetaRSI: 69% of RSI systems close their loop only on machine-checkable targets. Ladders: Reliable survey L0 output / L1 model / L2 scaffold / L3 improver / L4 criterion ("RSI begins at L3"); leezythu Optimization Ladder L0 prompts → L5 harness+weights; "Last AI Built by Humans" L1–L5 autonomy. Bounded self-refinement (fixed external evaluator) vs open-ended RSI (loop modifies its own evaluator/improver). Almost everything demonstrated is bounded, human-on-the-loop.
- **The community's own verdict: "the acceptor is the weak link."** PACE: greedy acceptance = 30–42% false commits. The statistical-gating papers (PACE, SEA, RSEA, agentdescent, autocontext, PROCTOR, HackProbe, Blind Curator, TAME, Falsifiable Release Gates) have 1–13-star repos or **no code at all**; the strict-improvement frameworks (SkillOpt 17k, GenericAgent 14k, darwin-skill 6k, auto-harness 537) ship "strict improvement on a held-out split, no ties". → The most actionable finding for a designer.
- The critique wave (convergent, independent groups): attribution (AI2: evolution ≯ test-time scaling at matched budget; Gideoni/Risi/Gal; "Worth Their Tokens"), compounding/retention ("Do Agent Optimizers Compound?": one-shot gains, GEPA transfers below baseline; SEAGym snapshot collapse; EvoHarnessBench harness-induced forgetting BWT −5/−4/−35%), who benefits (Lin et al.: update quality flat across tiers, benefit non-monotonic; HarnessDev: self-selection ≈ coin flip on held-out, 0/64 edits touched a verifier), mechanism (EvoTrace 30% byte-identical re-introductions; Demystifying Skills retrieval precision 29.6→3.3% at 100 skills; CTA +0.3pp), misevolution (SkillMisevo 21/21 unsafe; MLAS 40/40 payloads persisted through Hermes background review; OpenClaw's human queue blocked 40/40 "without any detection heuristic").
- Judges cannot be the final authority: "More Convincing, Not More Correct" (judge pass 0.72→0.94 while accuracy stays 0.20, survives 3-judge ensemble); Blind Curator cliff (judge false-pass > ~0.45 ⇒ retirement retires nothing); Memory Reward Inflation (self-grades endorse 31–54% of wrong answers; stronger re-graders share the bias); "Self-Authored Verification Is Unreliable". Responses converge on **PROCTOR's rule: mechanical rejection overrides LLM approval, never the reverse.**
- Emerging reporting standard (pinkbubblebubble checklist): multi-generation results incl. regressions & variance; a held-out verifier the system cannot rewrite; ablations of self-modification vs search vs memory; generalization to unselected tasks; full compute/trajectory/failed-attempt logs; explicit isolation/permissions/rollback/human interventions. Reviewers will ask for matched-budget test-time-scaling baselines.
- POSITIONING: the framework is **the verification / acceptance layer for harness-level (L2–L3) bounded self-improvement** — "governance-grade measurement of self-improvement", which the survey calls the emptiest area. It is what turns "my agent modified itself" into "the modification was sealed-evaluated, gated with error control, activation-checked, attributed, and is revertible". It is explicitly NOT another proposer.

## 3. Hard design rules the RSI literature imposes (each with its source)

1. **Sealed evaluation, fresh-container replay, fail-closed to 0** (RSI-Exam; MetaRSI Eq. 30; HarnessDev score-path isolation: self-report is never a scoring input; credit only from ground-truth artifacts).
2. **Model proposes, deterministic code adjudicates** (MetaRSI's single authority cut; PROCTOR "mechanical rejection overrides LLM approval, never the reverse"; dsh's deny-only guard so listener order cannot resurrect a denied action).
3. **Re-execute, don't stitch** (The Replay Gap: 3–8% replay validity for early interventions; 0/359 control flips vs 5/5 swap flips). Branch at k from a checkpoint, run candidate AND a same-config control arm; accept only deltas that clear the control distribution. Late fork points are safer. T=0 is not determinism (FP8 controls diverged 90–96%) → always measure the noise floor.
4. **Paired, anytime-valid, per-candidate error control + run-level spend** (PACE betting e-process; SEA's horizon-free CTHS schedule δ_k = δ₀/(Z·k·log²(k+1)), Z≈3.39, naive 1/(2k log²) over-spends 1.69×; SEA's ALG4 accepted 0 edits at ~50 tasks and was switched off → **evidence must accumulate across many cheap rounds / canary, and gate on denser proxies with a cascade**; per-task floors only on tasks with observed stability, k-of-n confirmation (own simulation §G)).
5. **Retention and adaptation measured separately** (EvoHarnessBench BWT/FWT; "additive-only cannot regress" is false; a single aggregate hides the trade-off).
6. **Activation + adherence are part of acceptance** (Lin et al.: update value is a property of the (update, consuming agent) pair; skill-load rate 25% vs 96%; adherence drifts .52→.13; HarnessDev: 18/108 declared mechanisms never fired; PAST-Bench mechanism-evidence score; Continual Harness: a tool silently no-op'd 842 turns while the agent claimed success). Gate = execution-based, agent-in-the-loop; require runtime-trace evidence the change actually executes.
7. **Two boundaries: admission at write + revocation at reuse** (SafeEvolve; SkillMisevo: three exposures suffice, benign mixing does not wash out → gates per-write, not periodic; retire on attributed harm; capacity-evict by utility−risk). Deterministic invariant: a revision may not silently drop a verification/reversibility requirement its ancestor asserted.
8. **Provenance never upgrades trust for agent-created artifacts** (MLAS: Hermes scanner exempted "agent-created" origin → 40/40 persisted; adversarial laundering by the same model evades same-model scanning). Treat agent-authored code as untrusted community code; cross-family judge; behavioral/semantic checks (egress, capability diff, sandboxed execution).
9. **Freshness**: reject candidates whose evidence was compiled before the last capability-altering change (MetaRSI Eq. 22).
10. **Diff == declared modification; declared-surface containment; identity match** (MetaRSI Eq. 27; HarnessPatch schema {hypothesis, operations, expected_effect, risks, evidence_refs}; AHE change_manifest predicted_fixes/risk_tasks → automatic EFFECTIVE/HARMFUL verdicts).
11. **Matched-budget test-time-scaling control** (AI2): accept a harness change only if its held-out delta beats what parallel-K / sequential-K on the unmodified harness achieves at the same rollout budget, and beats noise across seeds; include meta-agent tokens in cost.
12. **Cheating detection as a first-class signal**: canaries (a perfect score is evidence of cheating — PROCTOR), randomized caps, HackProbe-style probe banks, leakage scans on harness diffs for task names/paths/command sequences (AI2 found memorized paths despite prompt-level bans), evaluator-access ledgers.
13. **The gate itself is outside the mutable surface** and changes to the evaluator/improver are L4/L5 events requiring independent anchors or a human (RSI survey; MLAS "optimizer-optimizee collapse"; dsh trusted-branch weighted approval for changes to the gate).
14. **Invisible until it blocks something** (adoption anti-correlated with gating). Default = observe-only ledger + funnel; blocking opt-in per surface; first-week value = "here is what your agent changed, what it would have broken, and what never activated."

## 4. Refined thesis (for the design phase to test)

**A harness-agnostic acceptance layer for self-modifying agents = "CI/CD for RSI"**, shipped as hooks/plugins into the seams above, with one policy engine:
- **Record**: sessions → cassettes (prompt/response/tool I/O + git snapshot at start + run-integrity metadata: model actually served, completion status, budget). Zero new instrumentation on Claude Code (transcripts already exist).
- **Candidate**: every persistent write (skill/memory/prompt-note/hook/tool/loop-graph change) becomes a typed HarnessPatch with declared surface, hypothesis, expected effect, evidence refs, provenance taint; diff must equal declaration.
- **Sealed evaluation cascade** (cheap → expensive; fail-closed): static/schema/leak scan → activation smoke (does the consuming agent load & follow it?) → safety canary (30–100 domain probes; cross-family judge; mechanical override) → branched re-execution from checkpoints in a git-snapshot sandbox with a same-config control arm (noise floor) on the protected corpus (past successes with observed stability) → sealed held-out slice the proposer never sees → matched-budget TTS control when claiming improvement.
- **Decision**: paired anytime-valid e-process per candidate + run-level spend schedule; retention (BWT) and adaptation (FWT) as separate terms; per-task floor with k-of-n; multi-objective constraints (tokens, latency, harness size/context bloat, safety) with Pareto; rejected-edit archive fed back to the proposer; certificate ledger {rung, evaluator id, benchmark version, closure level, δ spent}.
- **Lifecycle**: quarantine → canary (fraction of live sessions; the e-process keeps running) → promote → attributed (clade-style pooled outcome stats per artifact; retire on utility≈0 or attributed harm) → revert (depth > 1, known-safe checkpoints). Loop-health funnel proposed→accepted→activated→attributed with alarms.
- **Acceptor benchmark**: inject known-good/neutral/harmful edits; report the gate's confusion matrix, evals/decision, safety decay, BWT/FWT, cost — the multi-generation benchmark the surveys ask for; PACE's "planted improvement among noise" + "no-real-gain stochastic" regimes; SkillMisevo/MLAS payloads as the safety suite.

Paper claim candidates: (a) "On the field's own ledgers (SkillOpt rejected buffer, AHE manifests, Meta-Harness summaries, HarnessDev's 73 versions, Continual Harness evolution_log), a sealed, paired, anytime-valid gate with activation and safety terms would have rejected X% of accepted edits as noise, caught Y% of regressions and Z% of unsafe artifacts, at W% of the evaluation cost" (the counterfactual HarnessDev explicitly skipped); (b) the null-effect audit of production stores; (c) measured divergence-point distributions for real refiner edits under branched re-execution (the middle case between VCR-naïve and Replay-Gap-hopeless).

## 5. Verified seam contracts (read from source, 2026-09-14)

### OpenClaw `skill_proposal_evaluate` (src/plugins/hook-skill.types.ts, src/skills/workshop/plugin-hooks.ts)
- Event: `{ correlationId?, proposal:{id, kind:"create"|"update", revision, revisionSha256, targetCurrentSha256?}, skill:{name, skillKey, description, source?}, candidate: BundleSnapshot, baseline?: BundleSnapshot, reason:"created"|"revised"|"manual"|"apply" }`; BundleSnapshot = `{ skillMd:{path,content,encoding,sha256,sizeBytes}, files[], treeSha256 }`.
- Result: `{ summary?, findings?:[{ruleId, severity:"info"|"warn"|"critical", message, file?, line?}], metrics?:Record<string,string|number|boolean>, evaluatorVersion?, mode?:"static"|"llm"|"baseline-comparison"|..., decision?:"pass"|"revise"|"block", decisionReason? }`.
- Outcome attribution: `{evaluatorId, pluginId, pluginVersion?}` + status `completed|skipped|error` — **only a completed `block` vetoes apply; `error`/`skipped` do NOT block (fail-open)** → our plugin must convert its own failures into explicit `block` when policy = fail-closed.
- Ledger: `skill_proposal_changed` events `{eventId, sequence, action: created|revised|evaluation_completed|applied|rejected|quarantined|stale, proposal:{id,kind,status,revision,revisionSha256,skillName,skillKey,skillFile}, evaluations[]}`; `skill_changed` `{action, source: workshop|clawhub|source-install|upload, before?, after?: {revision:{contentSha256, treeSha256}}}`. Hook registration supports `matcher`, `priority`, `timeoutMs`.
- Other relevant OpenClaw hooks: `before_tool_call`, `after_tool_call`, `tool_result_persist`, `before_message_write`, `llm_input`/`llm_output`, `before_agent_run`, `before_install`, `session_start/end`, `subagent_*`.

### Claude Code `claude plugin eval` (present in local CLI 2.1.258)
- Layout: `<plugin>/evals/<case>/prompt.md` (frontmatter: name, tags, plugins, runs=3, max_turns=10, timeout_seconds=300, allowed_tools, model, env) + `graders/*.md` (type: regex | tool_used | tool_order | file_exists | llm | baseline); optional case.yaml. Results → `evals/results/`.
- `--ablation with-without` (default when a plugin resolves): runs a no-plugin baseline arm and reports Δ; `tool_used: Skill` style graders are with-only "plugin fired" indicators, not part of score. `--threshold <0..1>` (default 1.0) → exit 1 if any case below. `--json [path]` full run result. `--judge-model` (default haiku). `--allow-tools` operator grant for gated tools.
- ⇒ Usable as an off-the-shelf **paired with/without evaluator** for the Claude Code adapter (a candidate skill/plugin vs none), with repeats=runs. Limits: haiku LLM grader default; per-case threshold, no sequential statistics; no sealed split; scores per case not per task-pair → our layer wraps it: fixed seeds/repeats, paired per-run outcomes, e-process over runs, protected-corpus cases auto-mined from cassettes.

### `claude plugin eval` — full contract (docs read 2026-09-14; feature requires CC ≥ 2.1.269, local CLI 2.1.258 already exposes the command)
- Isolation per run: throwaway home + workdir + config; `claude -p` child with ONLY the plugin loaded — no user settings, hooks, CLAUDE.md, MCP servers, other plugins, memory, skills; env allowlist + `EVAL_*`; eval dir hidden from the agent; Artifact off. Bash (if granted) runs under the OS sandbox: writes confined to workspace, home unreadable, network only to `WebFetch(domain:…)` grants; refuses to run unconfined.
- Case = dir with `prompt.md` (frontmatter: runs=3 [1–50], max_turns=10 [≤200], timeout_seconds=300 [≤3600], allowed_tools, model, append_system_prompt, env EVAL_*) and/or `case.yaml` (`schema_version "1.1"`, `context.scaffold_script` [runs as you, only with `--scaffold`], **`context.history_file` — a .jsonl transcript to resume; the prompt becomes the next user turn**, `context.add_dirs`).
- Graders (`graders/*.md`, `weight`, `arm: with-only|both`): `regex` (pattern/flags/match contains|not_contains|count:N, target last_message|trace|files|{source:file,path}|mock_calls), `tool_used` (tool, input_match, min, max), `tool_order` (before/after), `file_exists` (path glob, exists), `llm` (criteria, focus; 2-of-3 judge votes), `baseline` (baseline_file .jsonl + criteria: at least as good as reference transcript). No custom-code graders.
- Scoring: run score = weighted fraction of graders passed; case score = mean over runs; two arms by default (with / without plugin); `tool_used: Skill` and `arm: with-only` graders are excluded from score in both arms (plugin-fired indicators). `--threshold` (default 1.0) → exit 1; `--max-cost-usd` → exit 2 partial; `--json` schemaVersion 1 with `aggregates.{overallScore,casesPassed,meanDelta}`, `cases[].aggregates.{score,delta}`, `cases[].arms.with[].{error,aborted,skippedPaidGraders}`, `costUsd`.
- MCP mocks: `evals/mocks/<server>/<tool>.md` with `{{input.field}}`/`{{file:…}}`, `expect:` guards (violation → abort, score 0), `type: agent` mocks with `.replay/` recordings; `_tools.json` real schemas.
- ⇒ **Build accelerator for the Claude Code adapter:** compile each cassette into a case: `scaffold_script` = restore the git snapshot at session start; `history_file` = the recorded transcript prefix up to the fork point; prompt = the next user turn; graders = the session's own terminal verification (regex over a test-output file + `tool_used` asserting the test command ran) + `file_exists`/`regex{source:file}` on artifacts + optional `baseline` vs the original transcript. Candidate = the plugin/skill under test → `--ablation with-without` gives paired with/without runs in sealed isolation; `runs` = repeats; `--json` feeds our e-process. Limits to wrap: per-case threshold only (no sequential stats, no per-task floor, no run-level spend), `llm` judge default haiku (cross-family spot-check needed), Artifact/network off, no `updatedToolOutput` replay inside eval (externals must be mocked or the case must avoid them), cost = cases×runs×2 agent runs.

## 6. Practitioner + ecosystem lenses (gap_analyses_all.json, 2026-09-14) — what they REORDER

**Users' vocabulary is version control, not RSI.** Across ten trackers ~0 issues ask for statistical acceptance; dozens ask for diff / receipt / undo / budget. hermes-agent#12238 (r=38, the most-reacted loop-adjacent issue): "backup & version control for ~/.hermes so users can track how their agent evolved". prime-agent#1208: "/refine is invisible — users cannot tell what changed or that it even ran" (closed unfixed). codex#34668 "visible write receipt"; codex#30299 inspect/prune/delete a 4,896-line MEMORY.md; prime#684 diff before apply. ⇒ Product framing for users: **"git + CI for your agent's brain"**; RSI vocabulary for the paper.

**Gates fail in the field by starving, not by strictness.** hermes#105770: write_approval on → 77 memory + 164 skill writes pending for 8 weeks, no signal, several un-applyable; #94353 scanner-refused writes cannot be human-approved → users bypass both gates; OpenClaw shipped a hash-bound proposal ledger and flipped its default to ungoverned `auto`. ⇒ "Invisible until it blocks" must be: **silent on pass, loud on block, never silent when starving** (alarms on pending-queue age/size; batched push-notified review with diff+evidence, expiry, override path).

**The most user-felt failures are receipt problems upstream of fitness.** claude-code#82056 (48 comments): a session cannot tell whether its memory index loaded whole / truncated / not at all (+ unstable store slug); #92998 overflow silently drops the NEWEST entries (corrections lost, corrected text stays loaded); #90604 safety rule missed via wrong cache path. ⇒ **Session-level load & adherence receipts** (resolved store identity + hash, bytes available vs loaded, status complete|truncated|not_loaded|wrong_store; followed/contradicted from transcript) work with no learning loop at all — highest-impact, cheapest component.

**Ownership/write-authority must be enforced on the file path, not on one tool.** hermes#99729 "skill_manage's approval gate is a convention — write_file/patch/terminal reach ~/.hermes/skills/ directly"; #105921 review fork deleted four standing permission rules; #41939 agent rewrote weeks of hand work (fixed by opt-in `.protected`). gfpyc's incident: background fork rewrote a user-validated chrome-devtools skill at 02:17 with "close ALL Chrome windows", bypassing the ledger by writing the file directly. ⇒ per-artifact authority (user-validated immutable to unattended writers by default), content-addressed snapshots before every unattended write.

**Undo that actually restores** is missing everywhere: hermes#96962 rollback restores SKILL.md but not references/scripts; #83580 51/62 archived skills unrecoverable; #75228 rollback nests the skill inside itself; OpenViking#4178 wants one-click reversal of a session's entire memory impact. ⇒ snapshot whole learned-state tree; "undo everything session X did" with conflict check; verified round-trip.

**Cost is the silent killer.** codex#19105/#19732 Memories drained a weekly quota while idle → users disabled it; hermes#93057 same-model review replays 350–384k context; claude-code#71633 skill-creator eval burns half a usage window; darwin-skill#25 "how to afford evaluating one skill". ⇒ spend ledger per loop + per gate, daily caps, circuit breaker; **the floor must ride on evaluations the user already ran (hook-recorded test runs), not new rollouts.**

**Deterministic lint catches most cheap failures** (hermes#416 open since March, filed by the maintainer): frontmatter parses, referenced scripts exist, executable skill compiles, "verified" claims must cite a tool-output span, placeholder tokens (NNN/HH:MM) never in verified blocks (#89963 codified a phantom helper as "Verified"), no session-specific facts in global rules, dedup, freshness on host update.

**The operational safety users file** is not refusal decay: learned helplessness (#6051 transient Playwright failure → durable tool-avoidance), secrets persisted (#101351 PAT into .git/config; codex#41711 memories exfiltrate local-provider chats to OpenAI), permission rules deleted (#105921), 46 memory files silently deleted by "dreaming" (openclaw#84882). ⇒ safety canary = operational invariants + DLP + egress, plus the Misevolve refusal probes.

**Users are asking for exactly our mechanisms:** hermes#96704 RFC "paired-arm harness measuring whether agent-written skills actually help" (three arms; "cheapest arm needs no model runs, numbers within a day"; production data: 182 skills, many use_count=0, 3 clusters of same-topic duplicates); microsoft/SkillOpt#155 "replay mined tasks with a real agentic CLI in a throwaway worktree, gate on the diff" — maintainers endorsed with three binding constraints: **worktree is disposable state not a security boundary (real execution needs a container with isolated creds/config/network); outcomes must be pass/fail/inconclusive; agent execution off by default.** hermes#107914 "verify uncertain memory/skill writes against the live environment before committing" (cites arXiv 2609.11060 Grounding Agent Memory, Microsoft, Sep 10). Also 2608.11095 "Why Does CLAUDE.md Keep Growing? Catastrophic Remembering" (+226% instruction growth).

**Ecosystem lens:** OpenClaw's `skill_proposal_evaluate` seam has **zero third-party implementations** on GitHub (2026-09-14). ### ⇒ Component order for adoption (revised)
0. **Receipts & change feed** (load/adherence receipts per session; "what changed since yesterday, from which session, why"; before/after diff) — no loop needed, works for hand-written CLAUDE.md too.
1. **Snapshot + undo** (content-addressed learned-state tree; session-scoped revert with conflict check; verified round-trip).
2. **Ownership + lint** (path-enforced write authority; deterministic write-time checks; DLP/secret scrub; egress policy).
3. **Spend ledger + caps + starvation alarms** (loop-health funnel incl. pending-queue age).
4. **Self-serve "does my store help me?"** (cheapest arm first: activation/adherence from transcripts; paired sandbox replay only where re-executable, with A-vs-A′ null floor; pass/fail/inconclusive).
5. **The gate** (paired anytime-valid e-process + floors + safety canary + sealed evaluation) as the engine underneath 4 and as the OpenClaw/Hermes/Reef/dsh plugin.
6. **Acceptor benchmark on Harbor + acceptance-record profile filed with in-toto/OTel/EEE.**
